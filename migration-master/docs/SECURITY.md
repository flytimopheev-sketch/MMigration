# Безопасность Migration Master

Документ описывает модель угроз и меры защиты, реализованные в приложении.
Область: локальная сеть и рабочая станция пользователя. Данные не покидают
локальную сеть, облако не используется.

## 1. Принципы

1. **Никакого постоянного root.** GUI и CLI запускаются от пользователя.
   Привилегированные операции выполняет отдельный `migration-master-helper`
   через `pkexec` (PolicyKit) по белому списку.
2. **Никакого shell.** Внешние команды запускаются без интерполяции
   оболочки: аргументы передаются отдельными параметрами `std::process::Command`.
3. **Явное подтверждение опасных действий.** Перенос приватных SSH-ключей,
   выполнение post-migration hooks, установка пакетов, удаление и замена файлов
   требуют отдельного подтверждения.
4. **Резервное копирование перед изменениями** системных и пользовательских файлов.
5. **Секреты не сохраняются.** Пароль архива, passphrase и содержимое приватных
   ключей не пишутся в SQLite, журналы и отчёты.

## 2. Шифрование и целостность

| Механизм | Реализация |
|---|---|
| Шифрование архива | `age` (scrypt/passphrase) с поддержкой armor |
| Хеширование | SHA-256 для файлов и манифеста |
| Целостность | `verify` сверяет `manifest.json`, `checksum.sha256`, хеши файлов |
| Сложность пароля | `security::EncryptionConfig::estimate_strength` (оценка и метка) |

Пароль передаётся только через `--passphrase` или поле GUI и **нигде не
сохраняется**. Восстановление зашифрованного архива без пароля невозможно.

```bash
migration-master verify profile.rmm --passphrase '...'
```

## 3. Path traversal

Все пути, извлекаемые из архива, проходят через
`security::sanitize_relative_path` / `safe_join` / `validate_path`:

- запрещены `..` и абсолютные пути;
- результат должен оставаться внутри целевого каталога (лексическая
  нормализация + проверка `is_within`);
- отклонённые пути фиксируются в отчёте как ошибки.

Тесты: `security::tests::*`, `backup::tests::test_create_backup_rejects_paths_outside_base`,
`archive::tests::*`.

## 4. SSH-ключи (§4)

- Приватные ключи **не переносятся без явного согласия**
  (`include_private_ssh_keys = false` по умолчанию); в архив попадают только
  публичные ключи, `config`, `known_hosts`.
- Содержимое приватных ключей не выводится в журнал и отчёты
  (идентификация — по fingerprint, `security::redact_secret`).
- После восстановления права выставляются заново
  (`ssh_keys::fix_permissions`):

  | Путь | Права |
  |---|---|
  | `~/.ssh` | `0700` |
  | приватный ключ | `0600` |
  | публичный ключ | `0644` |
  | `authorized_keys` | `0600` |
  | `config` | `0600` |

- Проверка владельца: `security::is_owned_by`, `enforce_private_permissions`.
- Существующие ключи автоматически **не заменяются**; для новых рекомендуется
  Ed25519.

## 5. Привилегированные операции (§15)

`migration-master-helper` принимает только четыре команды и проверяет аргументы
до запуска:

| Команда | Проверки |
|---|---|
| `install-packages` | валидация имён пакетов, менеджер определяется автоматически |
| `install-policy` | источник — существующий файл, цель — фиксированный путь `/usr/share/polkit-1/actions/...` |
| `copy-system` | белый список префиксов: `/etc/cups`, `/etc/skel`, `/usr/share/migration-master` |
| `set-mode` | белый список префиксов: `/etc/cups`, `/etc/skel`, `/home`; права ≤ `07777` |

Действия PolicyKit (белый список `polkit::ALLOWED_ACTIONS`):

```
com.redos.migration-master.helper.install-packages
com.redos.migration-master.helper.configure-printers
com.redos.migration-master.helper.apply-system-settings
```

Файл политики: `resources/com.redos.migration-master.policy`.
Тест `polkit::tests::test_shipped_policy_matches_render` гарантирует, что файл
не разошёлся с кодом.

## 6. Журналирование и история (§16)

Таблицы SQLite: `migrations`, `migration_items`, `hosts`, `archives`,
`application_rules`, `operation_logs`, `backups`, `settings`.

**Хранится:** дата, тип, источник, цель, статус, длительность, количество файлов,
размер, ошибки, путь к отчёту.

**Не хранится:** пароли, passphrase, содержимое приватных ключей, секреты
приложений. Ключ `passphrase` помечен `skip_serializing` в `WizardConfig`.

## 7. Резервное копирование

Перед перезаписью существующих файлов создаётся резервная копия
(`backup::BackupManager`, по умолчанию `~/.local/share/migration-master/backups`)
с манифестом и хешами; копии можно проверить и восстановить:

```bash
migration-master restore profile.rmm --target /home/user --dry-run   # без изменений
```

## 8. Отказоустойчивость

- Отмена длинных операций по Ctrl+C через токен (`cancel`), проверяется в рабочих циклах.
- Атомарная запись файлов (временный файл + переименование).
- `dry-run` во всех разрушающих командах (`create`, `restore`, `migrate-ssh`).
  Режим **не оставляет следов**: файлы не создаются, каталог назначения не
  создаётся, резервная копия не делается (`wizard::create_backup` пропускается).
  Проверка свободного места в `dry-run` выполняется по ближайшему существующему
  родителю, чтобы оценка работала и для ещё не созданного каталога.
  Регрессия фиксируется тестами `archive::tests::test_dry_run_create_and_restore`
  и `test_dry_run_space_check_uses_existing_ancestor`.
- Повторный запуск после ошибки безопасен: незавершённые архивы не попадают в историю
  со статусом «успешно».

## 9. Проверка перед выпуском

```bash
cargo clippy --all-targets -- -D warnings
cargo test --release
```

Контрольные места в коде: отсутствие `unwrap()`/`expect()` в рабочих путях,
отсутствие `Command::new("sh")`, `shell: true` и строковой конкатенации команд.
