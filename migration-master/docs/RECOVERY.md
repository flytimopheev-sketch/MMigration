# Руководство по восстановлению после ошибки

Что делать, если миграция прервалась, завершилась ошибкой или завершилась
неуспешным статусом.

## 1. Не паникуйте: данные не потеряны

Migration Master **никогда не удаляет исходный профиль**. Все изменения
ограничены:

- целевым каталогом (`--target`);
- каталогом архива;
- резервными копиями в `~/.local/share/migration-master/backups`.

## 2. Определите состояние

```bash
# Итог последней операции
migration-master report --format txt --limit 5

# Что реально записано (dry-run покажет план)
migration-master restore profile.rmm --target /home/user --dry-run --passphrase '...'
```

Статусы в отчёте: `успешно`, `с ошибками`, `отменено`.

## 3. Типовые ситуации

### Ошибка «повреждённый архив» / checksum mismatch

```bash
migration-master verify profile.rmm --passphrase '...'
```

Если `verify` падает — архив повреждён на этапе переноса. Пересоздайте его на
исходной машине (`migration-master create`) или проверьте носитель
(`dmesg`, `fsck`). Частичное восстановление невозможно: целостность проверяется
по всем файлам.

### Ошибка «недостаточно места»

Проверьте свободное место в целевом каталоге; освободите пространство или
сузьте набор компонентов:

```bash
migration-master restore profile.rmm --target /home/user --components documents --dry-run
```

### Ошибка прав доступа (permission denied)

```bash
ls -ld /home/user
# .ssh должна быть 0700, приватные ключи — 0600
```

После восстановления права выставляются автоматически
(`ssh_keys::fix_permissions`); при сбое перезапустите восстановление
компонента `ssh_keys`.

### SSH: соединение не устанавливается

```bash
migration-master migrate-ssh user@host --dry-run   # диагностика
ssh -v user@host                                    # проверка вручную
```

Причины: недоступен порт 22, не тот ключ (`--identity`), не подтверждён
отпечаток узла, разные подсети. Проверку host key обходить **нельзя**.

### Ошибка «нет внешнего инструмента»

Установите недостающую утилиту (`tar`, `zstd`, `ssh`, `rsync`, `lpstat`) —
список виден на экране диагностики в GUI и в выводе `migration-master scan`.

### Миграция отменена (Ctrl+C)

Отмена штатная: завершённые файлы уже перенесены, недокомпонованный архив не
попадает в историю со статусом «успешно». Повторите команду — операция
возобновится с проверкой хешей.

## 4. Откат изменений на целевой системе

Если восстановление прошло с ошибками и файлы испорчены:

```bash
# 1. Резервные копии, созданные до перезаписи
#    (каталог: ~/.local/share/migration-master/backups)
#    найдите последнюю копию и восстановите её обычным распаковщиком
#    либо через manifest.json внутри копии.

# 2. Если резервной копии нет — восстановите из архива заново с
#    безопасной стратегией:
migration-master restore profile.rmm --target /home/user --strategy rename --passphrase '...'
```

Стратегия `rename` сохраняет повреждённые файлы как `*.old` — их можно
разобрать вручную.

## 5. Очистка

```bash
# Просмотр и удаление старых резервных копий
ls -lh ~/.local/share/migration-master/backups
rm -rf ~/.local/share/migration-master/backups/<id>
```

## 6. Сбор данных для отчёта об ошибке

```bash
migration-master config path
migration-master report --format json --output /tmp
tail -100 ~/.local/share/migration-master/logs/migration-master.log
```

Файл журнала: `~/.local/share/migration-master/logs/migration-master.log`
(ротация — `max_log_size_mb` из настроек, по умолчанию 10 МБ).

Не включайте в отчёт пароли и содержимое приватных ключей — они в лог не
попадают, но и не добавляйте их вручную.
