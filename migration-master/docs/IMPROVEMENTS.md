# План улучшений по итогам проверки 0.1.5

Дата проверки: 2026-11-06. Версия: 0.1.5 (коммит `8adb770`).
Метод: чтение кода, сверка документации с реализацией, анализ результатов
CI (Rust-тесты и сборка RPM прошли). Локального Linux/GTK на машине
разработчика нет, поэтому поведение GUI проверялось по коду и CI.

Документ описывает **найденные расхождения и предложения**, а не готовые
изменения. Порядок — по влиянию на пользователя.

## Кратко

Главные проблемы 0.1.5:

1. стратегия конфликтов `ask` молча пропускает существующие файлы;
2. компоненты `packages`, `printers`, `system_settings`, `cron_jobs` —
   заготовки, которые ничего не архивируют;
3. Firefox, Thunderbird, Git и shell-конфиги не попадают в архив, хотя
   правила приложений описывают их пути;
4. приватные SSH-ключи и `authorized_keys` нельзя включить через CLI/GUI;
5. CLI `restore` не делает автоматический backup, хотя документация это
   обещает;
6. `scan` и `create` сканируют разные наборы файлов.

## P0 — исправить до следующего релиза

### 1. `ask` должен спрашивать, а не пропускать

**Где:** `src/conflict_resolver/mod.rs` (`ConflictResolver::resolve`),
`src/archive/mod.rs` (`ArchiveManager::restore`), `src/ui/util.rs`
(`STRATEGY_LABELS`), `src/ui/gtk_app.rs` (страница восстановления),
`src/cli/mod.rs` (значение по умолчанию).

**Проблема.** При стратегии `Ask` без зарегистрированного обработчика
`resolve()` возвращает `Skip`. `ArchiveManager::restore` создаёт
`ConflictResolver` без интерактивного обработчика, а GUI выбирает `ask`
индексом 0 и CLI использует `ask` по умолчанию. В результате пользователь
думает, что программа спросит про каждый конфликт, а она молча оставляет
старые файлы. Это особенно опасно при восстановлении в существующий `$HOME`.

**Что сделать (минимум):**

- либо реализовать обработчик: в CLI — построчный вопрос в TTY, в GUI —
  диалог с вариантами «заменить / пропустить / сохранить оба / применить ко
  всем»;
- либо убрать `ask` из GUI/CLI до реализации и выбрать безопасный default
  (`rename`), а при явном `--strategy ask` без TTY выдавать ошибку;
- в отчёте показывать число файлов, пропущенных из-за конфликтов, крупной
  строкой, а не только в списке конфликтов.

**Тест:** создать архив с файлом, изменить целевой файл, выполнить restore с
`ask` без TTY и проверить, что возвращается понятная ошибка, а не «успех» с
пропуском.

### 2. Доделать или спрятать компоненты `packages`, `printers`, `system_settings`, `cron_jobs`

**Где:** `src/config/mod.rs` (`default_paths`), `src/wizard/mod.rs`
(`scan`), `src/system_settings/mod.rs`, `src/packages/mod.rs`,
`src/printers/mod.rs`.

**Проблема.** В `default_paths` эти компоненты указывают на файлы, которые
никто не создаёт:

- `~/.local/share/migration-master/package-list.json`;
- `~/.config/migration-master/system-settings.json`;
- `~/.config/migration-master/crontab.txt`;
- `~/.cups` — единственный реальный путь, но это только пользовательская
  конфигурация CUPS.

`SystemSettings::collect`, `SystemSettings::dump_dconf`,
`PackageManager::export_list`, `PrinterManager::collect` и
`PrinterManager::install_commands` не вызываются из основного потока. В GUI
эти компоненты выглядят как рабочие, но выбор `packages`/`system_settings`/
`cron_jobs` не добавляет в архив ничего.

**Что сделать:**

- **Пакеты:** при создании архива сохранять список (`rpm -qa`,
  предпочтительно только `dnf repoquery --userinstalled`) в manifest или
  отдельный файл; при восстановлении показывать diff и предлагать установку
  через helper с подтверждением, а не ставить всё автоматически.
- **Принтеры:** сохранять `lpstat -p -d` и `lpstat -v` (имя, модель, URI) в
  manifest; при восстановлении генерировать `lpadmin`-команды и выполнять их
  только через `pkexec`/helper.
- **Системные настройки:** вызывать `SystemSettings::collect` и
  `dconf dump /` при создании; при восстановлении применять пользовательский
  dconf без root, системные файлы — только через helper.
- **Cron:** сохранять `crontab -l` и восстанавливать `crontab <file>` от
  имени пользователя.
- Если это не входит в ближайший релиз — скрыть компоненты из GUI и помечать
  в CLI «не реализовано», чтобы не создавать ложное впечатление.

### 3. Добавлять пути правил приложений в скан

**Где:** `src/applications/mod.rs` (`builtin_rules`, `relative_paths`),
`src/wizard/mod.rs` (`scan`).

**Проблема.** Правила задают `.mozilla/firefox`, `.thunderbird`,
`.gitconfig`, `.bashrc`, `.zshrc` и другие пути, но `scan` обходит только
`component.default_paths`, а правила использует лишь для исключений и
размера/подсказок. Поэтому Firefox и Thunderbird **не переносятся**, хотя в
README и руководстве заявлен перенос настроек приложений. Chromium, VS Code,
systemd и файловые менеджеры попадают случайно — их пути лежат внутри
`.config`/`.local/share`.

**Что сделать:** при выборе `app_configs`/`app_data` добавлять
соответствующие `config_paths`/`data_paths` включённых правил, дедуплицировать
пути и соблюдать выключенные правила. Добавить тест: архив с `app_configs`
содержит `.mozilla/firefox/...` и `.thunderbird/...`.

### 4. Дать явный доступ к приватным SSH-ключам и `authorized_keys`

**Где:** `src/wizard/mod.rs` (`WizardConfig`,
`include_private_ssh_keys`, `include_authorized_keys`), `src/cli/mod.rs`,
`src/ui/gtk_app.rs`.

**Проблема.** Флаги существуют только внутри `WizardConfig`; CLI и GUI их не
выставляют. В результате приватные ключи и `authorized_keys` нельзя перенести
ни одним пользовательским способом. Документация 0.1.5 говорила «возможно
при явном включении флага», но включить его негде.

**Что сделать:** добавить в CLI `--include-private-ssh-keys` и
`--include-authorized-keys`, в GUI — выключенные по умолчанию переключатели с
предупреждением и подтверждением. После восстановления принудительно ставить
`0700` на `.ssh` и `0600` на приватные ключи. В отчёт не писать содержимое.

### 5. CLI `restore` должен делать backup или честно предупреждать

**Где:** `src/cli/mod.rs` (`Commands::Restore`), `src/wizard/mod.rs`
(`create_backup`).

**Проблема.** GUI-мастер создаёт резервную копию через
`MigrationWizard::create_backup`, а CLI-команда `restore` вызывает
`ArchiveManager::restore` напрямую. При этом `USER_GUIDE_RU.md` обещает
автоматическую копию перед изменением файлов.

**Что сделать:** в CLI перед restore с `replace`/`rename` создавать backup
затрагиваемых файлов через `BackupManager` (или требовать явный
`--no-backup`), а в документации указать разницу. Как минимум — выводить
предупреждение и путь, куда backup не создан.

### 6. Унифицировать `scan` и `create`

**Где:** `src/cli/mod.rs` (`Commands::Scan`, `scan_items`),
`src/profile_scanner/mod.rs`, `src/wizard/mod.rs`.

**Проблема.** `scan` использует `ProfileScanner`, а `create` — обход
`default_paths` в `MigrationWizard`. Наборы различаются: `scan` не показывает
`.cups`, `~/.config/systemd/user` и файлы-заготовки; `create` их включает.
Пользователь сканирует профиль, видит один размер, затем создаёт архив
другого размера.

**Что сделать:** один общий сканер для `scan` и `create` (или явно
документировать разницу). Добавить интеграционный тест: для одного `$HOME`
количество файлов и байт в `scan --json` и в manifest архива совпадает.

### 7. Исправить примеры с `--passphrase` и защитить пароль в CLI

**Где:** `README.md`, `migration-master/README.md`,
`migration-master/docs/*`.

**Проблема.** Примеры `migration-master create --output profile.rmm
--passphrase` без значения не работают: clap ожидает аргумент. Кроме того,
пароль, переданный аргументом, виден в `ps`/`top` и остаётся в истории
оболочки.

**Что сделать:**

- исправить примеры на `--passphrase '...'` (уже сделано в этом обновлении
  документации);
- добавить `--passphrase-file` и/или интерактивный ввод (`rpassword`) для
  CLI, чтобы пароль не попадал в `argv`;
- в GUI показывать индикатор стойкости и кнопку генерации пароля
  (`security::estimate_password_strength` уже есть, но не используется).

## P1 — функциональность и удобство

### 8. Предпросмотр и разрешение конфликтов в GUI

Сейчас страницы создания/восстановления сразу запускают операцию. В мастере
есть `preview()`, но GUI его не вызывает. Добавить экран «План»: сколько
файлов/байт, свободное место, какие компоненты реально дадут файлы, сколько
конфликтов, какие приложения нужно закрыть. Для конфликтов — диалог или
безопасный default `rename`.

### 9. XDG-каталоги вместо угадывания

`default_paths` перечисляет `Desktop`/`Рабочий стол`, `Documents`/`Документы`
и т.д. Правильнее читать `~/.config/user-dirs.dirs` (или `xdg-user-dir`) и
поддерживать произвольные локализованные каталоги. Это уберёт пустые
компоненты и дубли.

### 10. Пост-восстановительные действия

Добавить в отчёт и/или выполнить автоматически от пользователя:

- `fc-cache -f` после шрифтов;
- `systemctl --user daemon-reload` и список включённых юнитов;
- `update-desktop-database ~/.local/share/applications`;
- проверку прав `~/.ssh`;
- подсказку про повторный вход;
- применение `dconf dump` через `dconf load`, а не только копирование
  бинарного `~/.config/dconf/user`.

### 11. Установка пакетов: только user-installed

Список `rpm -qa` содержит ядра, драйверы и системные пакеты; устанавливать
его целиком на новую машину опасно. Нужен список `dnf repoquery
--userinstalled` (с fallback `dnf history userinstalled`), diff с целевой
системой, отчёт о недоступных пакетах и установка только после подтверждения
через helper.

### 12. Восстановление принтеров

Сохранять имя, модель, URI и параметры; генерировать `lpadmin`-команды.
Системный `/etc/cups` и установка драйверов требуют root — через helper.
Пользовательский `~/.cups` полезен только для клиентских настроек.

### 13. Системные настройки и dconf

Подключить `SystemSettings::collect`/`dump_dconf` к созданию архива,
хранить дамп как файл и применять его после входа в сессию. Системные файлы
(`/etc`) не копировать вслепую: они зависят от железа и сети.

### 14. Укрепление SSH-режима

- Экранировать удалённые пути: сейчас `scp`/`rsync` получают путь, склеенный
  через `:`, и домашний каталог с пробелом/спецсимволом ломает команду.
- `StrictHostKeyChecking=accept-new` — это TOFU, а не проверка. Показывать
  отпечаток и просить подтверждение.
- `rsync` использовать с `--partial` для возобновления, либо убрать
  «возобновление» из документации.
- `BatchMode=yes` означает, что пароль SSH не спросят — документировать
  требование ключа/агента.

### 15. Пароль в GUI и CLI

Подтверждение пароля (два поля), индикатор стойкости, генерация, возможность
показать/скрыть. Для CLI — файл/интерактивный ввод. После использования
обнулять строку, насколько это возможно в Rust.

### 16. Прогресс, отмена и отчёт

В GUI есть прогресс-бар, но нет кнопки отмены, хотя `CancelToken` уже есть.
Добавить отмену, итоговый экран с числами «восстановлено/пропущено/ошибки» и
кнопку «Открыть отчёт». В CLI при `ask` печатать предупреждение о том, что
интерактив не реализован.

### 17. Метаданные и пустые каталоги

Сейчас сохраняются права файлов, но не владелец, ACL, xattr, SELinux,
capabilities, жёсткие ссылки и пустые каталоги. Для «образа профиля» это
обычно допустимо, но нужно явно писать в отчёте. Для полного образа
использовать `rsync -aHAX`/`tar --xattrs --acls` под root.

## P2 — качество и инфраструктура

### 18. Версионирование формата и фактическая документация

README описывает отдельные `data.zst` и `checksum.sha256`, но реальный
`.rmm` — это zstd-tar с `manifest.json` первой записью, при необходимости
целиком зашифрованный age. Привести схему в документации к реальности и
предусмотреть версию формата для будущих полей (`packages`, `printers`,
`dconf`).

### 19. Интеграционные тесты

Добавить:

- e2e CLI: `create` → `verify` → `restore` во временный `$HOME`;
- сравнение `scan` и manifest;
- тест `ask` без TTY;
- тест путей app rules (Firefox/Thunderbird);
- тест флагов приватных ключей;
- e2e GUI: создание и восстановление через мастер (headless).

### 20. Проверка документации в CI

Примеры команд должны проверяться хотя бы `--help`/clap-парсером. Отдельно
синхронизировать версию и дату man-страницы (сейчас `0.1.0`, `2024-01-15`,
хотя релиз 0.1.5).

### 21. Кроссплатформенность и дистрибутивы

Проверять сборку/тесты в контейнерах Debian и РЕД ОС, а также на разных
версиях libadwaita (в CI уже есть матрица 1.2/1.5 — сохранить). Учесть
различия `dnf`/`apt`, путей XDG и наличия `lpstat`/`pkexec`.

### 22. Упаковка

Добавить в `%doc` новые руководства (`HOST_IMAGE.md`, `IMPROVEMENTS.md`),
проверить, что man-страница обновляется при смене версии, и не забывать про
`CHANGELOG.md`.

- Ядро архивов: zstd-tar, `manifest.json`, SHA-256, age, защита от path
  traversal, атомарная запись, dry-run.
- Разделение публичных и приватных SSH-ключей, проверка прав после restore.
- Резервное копирование в GUI-мастере и история операций в SQLite.
- Понятные отчёты и коды возврата; CI собирает RPM и проверяет GUI/CLI.
- Документация подробная; после исправлений примеров и статусов компонентов
  она станет заметно надёжнее.
